# Programming Fundamentals Using C++

> A complete, free, self-study course — from your very first program to
> object-oriented design — in 16 units and 32 sessions.

**Read this course online:** <https://nadeem-majeedch.github.io/Programming-Fundamentals-Using-C-/>

**Programming Fundamentals Using C++** is a beginner course you can study
entirely on your own — no classroom, no fees, no prior experience required.
You start from what a program actually *is*, and week by week you build up to
real programs: interactive input/output, collections, file storage, and
object-oriented design, finishing with a capstone project.

- **16 units** · **32 sessions** · about **5–7 hours per week**
- Every concept comes with **examples, exercises, labs, quizzes, and
  revision material**
- Every lab and quiz has a **complete worked solution** — you check your own
  work and never get stuck

## 🎯 What you will learn

By the end of this course you will be able to:

1. **Write, compile, and run** C++ programs on your own computer.
2. **Store and process data** with variables, types, and expressions.
3. **Write interactive programs** that take input and produce formatted
   output.
4. **Make decisions and repeat work** with `if`/`else`, `switch`, and loops.
5. **Break programs into functions** — and design programs top-down before
   writing them.
6. **Manage collections of data** with arrays and `std::vector`, and search
   and sort them.
7. **Process text** with the C++ string library.
8. **Save and load data** with files so your programs remember between runs.
9. **Understand pointers and dynamic memory** — what they are and when to use
   them.
10. **Design classes** — the foundation of object-oriented programming — and
    combine objects into realistic programs.
11. **Debug systematically**: read compiler errors, form hypotheses, and test
    them.
12. **Complete three projects**, including a capstone that integrates
    everything.

## 🗺️ The learning path

The course moves through twelve territories, each building on the last:

```text
Problem solving        →  think before you code: decomposition, IPO,
  (Week 0)                algorithms, pseudocode, trace tables
C++ fundamentals       →  programs, variables, types, operators,
  (Weeks 1–3)             input & output
Control flow           →  decisions (if/else/switch) then loops
  (Weeks 4–6)             → PROJECT 1
Functions              →  parameters, returns, scope, references,
  (Weeks 7–8)             top-down design
Arrays & strings       →  collections, then searching & sorting,
  (Weeks 9–11)            then text processing → PROJECT 2
Files & memory         →  persistent data, then pointers, dynamic
  (Weeks 12–13)           memory, and ownership
OOP                    →  records → classes → objects in
  (Weeks 14–15)           collections → PROJECT 3
Modern C++ & STL       →  the professional toolkit: RAII, smart
  (Week 16 +)             pointers, containers, algorithms
```

Every stage builds on the one before it — that is why the units are studied
in order.

## 🧭 How to study

This course is designed to be studied **without an instructor**. The method,
in one line: **read → run → modify → solve → debug → revise**.

1. **Read** the session page slowly. Run every example as you meet it — never
   read code you haven't run.
2. **Modify** each example: change a value, break it on purpose, predict the
   new output, and check.
3. **Solve** the module's exercises — attempt first, then check answers.
4. **Debug** — do the unit's Debug It activity *before* looking at its fix.
5. **Lab** — build the lab, compare with the solution, score yourself with
   the rubric.
6. **Quiz** — attempt all 10 questions, then read the answer key's
   explanations. Score ≥ 90%: move on. 70–89%: revisit flagged sections.
   < 70%: redo exercises + revision sheet first.
7. **Revise** with the unit's revision sheet, then add its flashcards to your
   personal deck.

**Rules of thumb**

- Never skip a unit — later units assume earlier ones.
- Type every example by hand at least once; never copy-paste what you are
  learning.
- Stuck? Re-read, modify, re-run, then check the
  [FAQ](docs/faq.md#troubleshooting-quick-answers) — and only then search
  online.
- Prefer understanding to finishing: a unit is *done* when the lab works and
  the quiz is ≥ 90%, not when the pages have been read.
